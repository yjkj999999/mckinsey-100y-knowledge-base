# 麦肯锡核心方法论

> 来源：麦肯锡100年知识库核心方法论精选

---

## 1. 金字塔原理 (Pyramid Principle)

**发明者**: Barbara Minto, 麦肯锡首位女咨询顾问

**核心思想**: 结论先行，自上而下，MECE分类

### 金字塔结构
```
        [核心论点/结论]
        /              \
  [论点A]          [论点B]
  /    \           /    \
[证据1] [证据2]  [证据3] [证据4]
```

### 应用规则
1. **纵向**: 上一层是下一层的总结，下一层是上一层的支撑
2. **横向**: 同一层级的内容必须 MECE (相互独立，完全穷尽)
3. **序言**: SCQA框架 — Situation(情境) → Complication(冲突) → Question(问题) → Answer(回答)

### 实践要点
- 任何表达都从"结论"开始
- 每个论点不超过3-5个支撑论据
- 支撑论据之间必须逻辑独立
- 检验方法：只看第一层能否回答核心问题

## 2. 结构化战略思维

**来源**: 《麦肯锡结构化战略思维：如何想清楚、说明白、做到位》

### "切"的艺术 (N-C-E法则)
- **N**ew: 切分维度必须产生新的洞察
- **C**omplete: 切分必须完全穷尽
- **E**xclusive: 切分必须相互独立

### 结构化分析维度
1. **按子品类切** — 市场细分
2. **按流程切** — 价值链分析
3. **按地理切** — 区域分析
4. **按时间切** — 周期分析
5. **按客户切** — 人群画像

### 结构化表达
- **论**: 核心观点先行
- **证**: 数据和事实支撑
- **类**: MECE分类组织
- **比**: 量化对比强化说服力

## 3. 假设驱动问题解决 (Hypothesis-Driven Problem Solving)

### 六步法
1. **界定问题** — 明确问题的边界和期望
2. **分解问题** — 用Issue Tree将大问题拆解为可验证的子假设
3. **优先排序** — 80/20法则，聚焦关键假设
4. **制定工作计划** — 为每个关键假设设计验证方法
5. **关键分析** — 收集数据验证或推翻假设
6. **综合论证** — 将分析结果结构化呈现

### 关键原则
- 先假设，后验证（而非先收集数据再找结论）
- 每个假设必须是可证伪的
- 快速迭代：推翻假设比证实假设更有价值
- 避免确认偏误：主动寻找反对证据

## 4. Issue Tree (逻辑树分析)

### 三种逻辑树
1. **What树** (问题拆解树)
   - 将大问题分解为小问题
   - 用途：理解问题全貌
   - 示例："利润为什么下降？" → 收入减少？成本增加？

2. **Why树** (原因分析树)
   - 挖掘问题的根本原因
   - 用途：找到问题根因
   - 示例："收入为什么减少？" → 客户减少？单价降低？产品线变化？

3. **How树** (解决方案树)
   - 生成和评估解决方案
   - 用途：制定行动方案
   - 示例："如何增加收入？" → 获取新客户？提高单价？交叉销售？

### Issue Tree构建规则
- 每一层都必须MECE
- 分解到可以采取行动的层级为止
- 每个叶节点都可以独立验证

## 5. 4S法 (State-Structure-Solve-Sell)

**来源**: 《像高手一样解决问题》— 伯纳德·加雷特 & 科里·菲尔普斯 & 奥利维耶·西博尼

### S1: State (界定问题)
- 问题是什么？
- 谁的问题？
- 问题的边界是什么？
- 成功的标准是什么？

### S2: Structure (结构化分析)
- 将问题拆解为可管理的子问题
- 建立分析框架
- 识别关键变量和关系

### S3: Solve (求解)
- 收集数据验证假设
- 量化分析
- 评估替代方案
- 推荐最优解

### S4: Sell (推介方案)
- 构建有说服力的故事线
- 用数据可视化支撑论点
- 预判反对意见
- 设计行动路线图

## 6. 零基准思考 (Blank Sheet of Paper)

**核心思想**: 抛弃现有框架和惯性思维，从空白页开始重新思考

### 应用场景
- 进入新市场时，不参考现有战略
- 重新设计业务模式时，不受历史限制
- 解决看似无解的问题时，跳出固有思维

### 实践方法
1. 假设你刚进入这个行业，你会怎么做？
2. 如果没有任何历史约束，最优方案是什么？
3. 从客户需求出发，重新设计端到端流程
4. 与行业外专家交流获取跨界灵感

## 7. MECE原则 (Mutually Exclusive, Collectively Exhaustive)

**定义**: 相互独立，完全穷尽

### 检验方法
- **相互独立**: 没有任何重叠 → A ∩ B = ∅
- **完全穷尽**: 没有任何遗漏 → A ∪ B = 全集

### 常见MECE切分维度
| 维度 | 示例 |
|------|------|
| 时间 | 过去/现在/未来 |
| 空间 | 国内/国际 |
| 程度 | 高/中/低 |
| 过程 | 输入/处理/输出 |
| 角色 | 生产者/消费者/监管者 |
| 财务 | 收入/成本/利润 |

### 常见非MECE错误
- 重叠：按"线上"和"移动端"分类（移动端是线上子集）
- 遗漏：按"国内"和"欧美"分类（遗漏其他地区）
- 混维：按"大客户"和"长期客户"分类（两个维度混合）

## 方法论应用决策树

```
面对商业问题
├── 需要理解问题全貌？ → Issue Tree (What树)
├── 需要找到根本原因？ → Issue Tree (Why树) + 5 Whys
├── 需要制定解决方案？ → 4S法 + Issue Tree (How树)
├── 需要沟通汇报？ → 金字塔原理 + SCQA
├── 需要突破思维局限？ → 零基准思考
└── 需要快速验证假设？ → 假设驱动六步法
```
